# Индивидуальная маркетинговая стратегия

Отдельный проект. Анкета размещается на GitHub Pages, серверная часть — на Amvera, заказы — в GetCourse.

## Текущее состояние
Подготовительная версия. Анкета еще не предоставлена. Сервер отвечает на /healthz; публичных методов создания заказов пока нет. Реальные данные не отправляются.

## План интеграции
1. После получения контактов и согласия на обработку данных создать сессию и сохранить уникальный номер заказа до первого запроса к GetCourse.
2. При начале анкеты создать заказ по этому номеру. При повторах использовать тот же номер; ответ API проверять.
3. Промежуточные ответы хранить в постоянном хранилище Amvera /data. Доступ к сессии только по непредсказуемому токену, не по email.
4. После полной проверки обязательных вопросов обновить тот же заказ через deal_number и передать вопросы и ответы в deal_comment. Статусы оплаты не менять. Проверить сохранение примечания и влияние обновления на состав и цену заказа на тестовом предложении.
5. При сбоях сохранять состояние отправки и повторять запрос с тем же номером. Не сообщать об успешном завершении до подтверждения API.

## Amvera
Создать приложение marketing-strategy и подключить этот репозиторий (main). Конфигурация в amvera.yml. Проверить доступность /healthz. Постоянное хранилище /data зарезервировано для будущей базы. Настройки и ключи вводить только в защищенных переменных окружения Amvera:
- GETCOURSE_ACCOUNT — имя аккаунта (без домена)
- GETCOURSE_API_KEY — секретный ключ
- GETCOURSE_OFFER_ID — ID предложения
- GETCOURSE_LIVE — 0 по умолчанию; включать только после настройки и тестирования

Ключи, заявки, ответы и базы данных не коммитить. Не записывать данные клиентов или ключ в логи. Перед публикацией согласовать политику обработки, сроки хранения и ограничения на длину ответов. Не принимать заявки на неподключенной странице.

## GitHub Pages
В Settings → Pages выбрать Deploy from a branch, main, / (root). Сейчас index.html — заглушка, будет заменена готовой анкетой.
